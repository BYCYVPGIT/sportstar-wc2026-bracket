# Data Pipeline & Live Scoring Design
**Date:** 2026-06-04  
**Project:** Sportstar FIFA WC 2026 Bracket Challenge  
**Status:** Approved

---

## Overview

Build the full backend pipeline to:
1. Collect live tournament results from football-data.org automatically
2. Persist user bracket submissions to Supabase
3. Score every bracket against real results after each match
4. Serve a live leaderboard

The scoring engine (`lib/scoring.ts`) and all TypeScript types are already written. This spec covers the plumbing that connects them to real data.

---

## Database Schema (Supabase / PostgreSQL)

### `bracket_submissions`
```sql
short_code       TEXT         PRIMARY KEY
display_name     TEXT         NOT NULL
group_ranks      JSONB        NOT NULL   -- Partial<Record<GroupCode, [string,string,string,string]>>
knockout_picks   JSONB        NOT NULL   -- Record<string, string>  slotCode → teamId
tiebreakers      JSONB        NOT NULL   -- { goldenBootTeam: string, finalTotalGoals: number }
score            INTEGER      NOT NULL DEFAULT 0
submitted_at     TIMESTAMPTZ  NOT NULL
updated_at       TIMESTAMPTZ  NOT NULL DEFAULT now()
```
- `short_code` is the existing value generated by `generateShortCode()` in `lib/bracket.ts`
- Upserted (not inserted) so re-submissions overwrite gracefully pre-lock
- `score` is recomputed server-side after every cron sync

### `tournament_results`
```sql
season            TEXT         PRIMARY KEY DEFAULT '2026'
group_standings   JSONB        NOT NULL DEFAULT '{}'   -- Record<GroupCode, [id,id,id,id]>
knockout_results  JSONB        NOT NULL DEFAULT '{}'   -- Record<slotCode, teamId>
golden_boot_team  TEXT                                 -- team ID
final_total_goals INTEGER
last_synced_at    TIMESTAMPTZ
```
- Single-row singleton table (keyed by season = '2026')
- Upserted by the cron job after every sync
- Row is created empty at schema setup; cron fills it in progressively

## API Routes

All routes live under `app/api/` using Next.js App Router conventions.

### `POST /api/brackets`
- **Called by:** `lib/store.ts` → `submitBracket()` (fire-and-forget after local state update)
- **Body:** `{ shortCode, displayName, groupRanks, knockoutPicks, tiebreakers, submittedAt }`
- **Action:** Upserts into `bracket_submissions`; computes initial score against current `tournament_results`
- **Response:** `{ shortCode, score }`
- **Auth:** None required (public submission)

### `GET /api/brackets/[code]`
- **Called by:** `app/b/[code]/page.tsx` (share page)
- **Response:** Single bracket row or 404
- **Auth:** None (public read)

### `GET /api/leaderboard?limit=50&offset=0`
- **Called by:** `app/leaderboard/page.tsx`
- **Response:** Array of `LeaderboardEntry` with `rank`, `displayName`, `shortCode`, `score`, `percentile`
- **Pagination:** `limit` + `offset` query params; default limit 50
- **Auth:** None (public read)

### `GET /api/cron/sync-results`
- **Called by:** Vercel Cron (every 15 min)
- **Protected by:** `Authorization: Bearer $CRON_SECRET` header — returns 401 otherwise
- **Actions:**
  1. Fetch finished matches from `GET /v4/competitions/2000/matches?status=FINISHED`
  2. Fetch group standings from `GET /v4/competitions/2000/standings`
  3. Map results to internal types (slotCodes, teamIds)
  4. Upsert `tournament_results` row
  5. Recalculate score for every `bracket_submissions` row using `computeFullScore()`
  6. Batch-update `score` + `updated_at` in `bracket_submissions`
- **Response:** `{ synced: true, matchesProcessed: N, bracketsRescored: M }`

## football-data.org Integration (`lib/football-data.ts`)

**Base URL:** `https://api.football-data.org/v4`  
**Auth:** `X-Auth-Token: $FOOTBALL_DATA_API_KEY` header  
**Competition ID:** `2000` (FIFA World Cup — reused each edition)

### Key mappings

**Round labels → stage:**
```
"LAST_32"        → r32
"LAST_16"        → r16
"QUARTER_FINALS" → qf
"SEMI_FINALS"    → sf
"FINAL"          → final
"THIRD_PLACE"    → third  (may appear as "PLAY_OFF_FOR_THIRD_PLACE")
```

**Match index within round → slotCode:**  
Matches within each round are ordered by `utcDate`. The nth match in round `LAST_32` maps to `R32-Mn`. Same pattern for all rounds.

**Winner extraction:**  
- Regular time: compare `score.fullTime.home` vs `score.fullTime.away`  
- Extra time/penalties: use `score.winner` field (`"HOME_TEAM"` or `"AWAY_TEAM"`)  
- Map winning team's `tla` (3-letter code) → internal `teamId` via a lookup table in `lib/football-data.ts`

**Golden Boot:** Not available directly from match data. Will be null until manually set or until a dedicated endpoint is available post-tournament.

## Bracket Submission Flow

**Current flow (unchanged):**
1. User fills bracket in browser → stored in Zustand + localStorage
2. User clicks "Lock & submit" → `store.submitBracket()` sets `status: 'submitted'` locally

**Addition to `lib/store.ts` → `submitBracket()`:**
```ts
// After setting local state:
fetch('/api/brackets', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ shortCode, displayName, groupRanks, knockoutPicks, tiebreakers, submittedAt }),
}).catch(err => console.error('[bracket submit]', err));
```
- Fire-and-forget: local state updates immediately regardless of network
- No user-facing error if POST fails (bracket is still in localStorage; can retry)
- If the POST succeeds but the user re-submits (pre-lock), the upsert overwrites cleanly

## Leaderboard Page Update

`app/leaderboard/page.tsx` is converted from a static Server Component with mock data to a dynamic Server Component that fetches from `/api/leaderboard`.

- `MOCK_ROWS` array is removed
- `STAGES` progress section is updated to show real scores per stage (from `tournament_results`)
- Page revalidates every 60 seconds (`export const revalidate = 60`)
- Falls back to empty state gracefully if DB is unavailable

## Cron Schedule (`vercel.json`)

```json
{
  "crons": [
    { "path": "/api/cron/sync-results", "schedule": "*/15 * * * *" }
  ]
}
```
Runs every 15 minutes — well within football-data.org free tier (10 req/min). During non-match days the sync is a no-op (no new FINISHED matches).

- Golden Boot automatic resolution (set manually post-tournament)
